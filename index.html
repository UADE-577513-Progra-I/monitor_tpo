Criterios de evaluación

Detalle de los requisitos considerados para marcar cada ítem como completado.

1 Definición de identidad del equipo

El Spreadsheet TPO deberá tener completo el Alias / Nombre del grupo.

2 Elección del tema

El Spreadsheet TPO deberá contener el nombre del tema a desarrollar, seleccionado del listado propuesto por la cátedra o propuesto por el propio grupo.

En todos los casos, el tema deberá ser consensuado y aprobado por el docente.

3 Conformar el repositorio en GitHub

El Spreadsheet TPO deberá contener el username de GitHub de cada integrante.

Cada integrante deberá aceptar la invitación enviada por el docente para quedar oficialmente incorporado al repositorio como colaborador.

4 Creación del archivo README.md

En la rama main del repositorio deberá existir un archivo README.md que incluya:

  • Tema elegido.
  • Integrantes: tabla con nombre y apellido, número de legajo y nombre de usuario de GitHub de cada integrante.
  • Descripción del proyecto: deberá describir brevemente el proyecto y delimitar claramente su dominio de aplicación. No se aceptarán descripciones genéricas; deberá especificarse el contexto concreto, el propósito del sistema y el ámbito en el que será utilizado.
Ejemplo de descripción

“Sistema para la gestión y venta de entradas de recitales de música, que permita administrar artistas, eventos, ubicaciones y ventas realizadas”.

También deberá incluirse un listado preliminar de funcionalidades previstas, de acuerdo con la temática y el dominio seleccionados.

Ejemplo de funcionalidades

Registrar y administrar artistas, crear eventos, gestionar ubicaciones y precios, registrar la venta de entradas, consultar disponibilidad y generar reportes de ventas.

5 Modelo Entidad–Relación

Subir al repositorio un documento en formato PDF o JPG que contenga el Diagrama Entidad–Relación (DER) del sistema.

  • Entidades con sus respectivos atributos y clave primaria.
  • Relaciones entre entidades con su correspondiente definición de integridad referencial.
6 Tablero Kanban

En la pestaña Projects del repositorio se encontrará un tablero Kanban creado por el docente.

Backlog

  • Listado de tareas definidas por el equipo.
  • Asignación equitativa entre los integrantes: mínimo 3 tareas por persona.

Status

En esta primera entrega no es obligatorio que existan tareas en estado In Progress.
